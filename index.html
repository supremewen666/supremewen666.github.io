🌱研究兴趣Research interests

此前，我主要关注递归式自我改进（RSI）和 Agent 记忆。我更感兴趣的问题是：持久记忆如何支持持续学习、记忆的扩展规律（memory scaling）是什么，以及如何在减少人工介入的同时保持可控、可评估的改进。My earlier interests centered on recursive self-improvement (RSI) and agent memory: how persistent memory can support continual learning, what its scaling behavior looks like, and how improvement can remain controllable and measurable with less human intervention.

研究思路与具体方向Research perspective & directions

这些探索让我开始关注更底层的系统机制。我的一个判断是，Agent 的长期演化不仅取决于记忆策略，还受到执行状态与资源管理方式的约束。我想从 OS 的视角进一步研究这些问题，而不只停留在提示词或应用层设计。This exploration led me to lower-level systems mechanisms. My working view is that long-term agent evolution depends not only on memory policies, but also on how execution state and resources are managed. I want to investigate these questions from an OS perspective, beyond prompts and application-level design.

  • AI 执行状态管理：研究执行状态（包括 KV Cache 等运行时状态）如何跨内存、存储、网络与进程边界被高效、正确地管理。AI execution-state management: efficiently and correctly managing execution state, including runtime state such as the KV cache, across memory, storage, networks, and process boundaries.
  • 跨层资源协调：探索框架、运行时、驱动与设备之间的协同，以及 GPU 资源的复用、隔离与抢占。Cross-layer resource coordination: cooperation across frameworks, runtimes, drivers, and devices, including GPU sharing, isolation, and preemption.
  • OS 与 AI infrastructure：探索 LLM 与内核态／用户态系统机制的结合，以及以系统机制为核心的性能优化。OS and AI infrastructure: studying how LLMs interact with kernel- and user-space mechanisms, and improving performance through systems design.

记忆策略之外的问题Beyond memory policies

这几个月，我接触了不少递归式自我改进（RSI）相关工作，也看了 LLM、Agent 和 Skill 中的记忆设计。我还没有找到一个让我足够信服的答案：怎样让这些机制真正支持长期学习，而不只是改善检索或延长上下文？又怎样在减少人工介入（HITL）的同时，让改进保持可控、可检验？Over the past few months, I have explored recursive self-improvement (RSI) and memory designs for LLMs, agents, and skills. I have yet to find an answer that fully convinces me: how can these mechanisms support long-term learning rather than merely improve retrieval or extend context? How can they reduce human-in-the-loop (HITL) intervention while keeping improvement controllable and testable?

我也关心 memory scaling。相比只说“更多记忆会更好”，我更想知道：经验、存储与计算预算怎样共同影响性能？能否建立像 Chinchilla LLM scaling law 那样清晰、可检验的规律？这对我仍是一个想继续研究的问题，而不是已经得出的结论。I am also interested in memory scaling. Beyond saying that more memory should help, I want to understand how experience, storage, and compute budgets jointly affect performance. Can we establish relationships as clear and testable as the Chinchilla LLM scaling law? For me, this remains a research question rather than a settled conclusion.

为什么开始关注 OSWhy I am turning toward OS research

想得越多，我越觉得问题可能不只在应用层的记忆策略。Agent 还需要管理执行状态、协调资源，并在不同边界之间保持正确性。我想知道，操作系统在复用、隔离、调度和持久化方面积累的设计，能否帮助我们重新理解这些问题。The more I think about it, the less likely it seems that application-level memory policies alone are the whole story. Agents also need execution-state management, resource coordination, and correctness across boundaries. I want to understand whether OS ideas about sharing, isolation, scheduling, and persistence can help us frame these problems differently.

GPU 资源管理也让我注意到跨层协调的重要性：相关能力分散在框架、运行时、驱动和设备中，普通 CPU 调度器并不能独自完成所有管理工作。我的一个研究假设是，记忆策略、后训练与 KV Cache 等运行时状态之间的协同，可能需要更明确的系统机制支撑。GPU resource management has also drawn my attention to cross-layer coordination. Responsibilities span frameworks, runtimes, drivers, and devices; a conventional CPU scheduler cannot manage everything on its own. One hypothesis I want to investigate is that coordination among memory policies, post-training, and runtime state such as the KV cache needs more explicit systems mechanisms.

接下来想做的事What I want to work on next

我希望有机会参与 OS 相关研究，探索 AI 执行状态如何跨内存、存储、网络与进程边界被高效且正确地管理，也关注 LLM 与内核态／用户态机制的结合，以及以系统机制为核心的 AI infrastructure 和性能优化。I hope to contribute to OS research on managing AI execution state efficiently and correctly across memory, storage, networks, and process boundaries. I am also interested in interactions between LLMs and kernel- or user-space mechanisms, and in AI infrastructure and performance optimization grounded in systems design.
